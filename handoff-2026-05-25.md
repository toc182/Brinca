### Session 2026-05-22 — iOS 26 modal header glitch + sync toast (categories)

**Header blur on iOS 26 modal sheets.** `react-native-screens` 4.24.0's `headerBlurEffect` doesn't render visible blur on `presentation: 'modal'` screens on iOS 26 — upstream issue [#4081](https://github.com/software-mansion/react-native-screens/issues/4081), no fix released. Initial implementation was inline in `CreateDrillScreen`; later extracted to a shared `ModalHeader` and applied to every push-navigated screen inside the `(settings)` sheet so the iOS 26 push-transition glitch (header snaps down on entry) goes away.

**Categories sync bug.** Local activity stored `category = 'Therapy'` (capitalized), violating Supabase check constraint requiring lowercase. Drill + downstream rows then blocked behind RLS. Fixed [`src/features/activity-builder/screens/CreateActivityScreen.tsx`](src/features/activity-builder/screens/CreateActivityScreen.tsx) to store lowercase with a display-label map. ### Session 2026-05-23 to 2026-05-25 — sync queue self-heal

**The problem.** Migration 0002's third clause only reset `table_name = 'drills'` failed entries. Nine downstream queue rows (tracking_elements, sessions, drill_results, element_values) that had hit `retry_count = 10` while the original chain was broken stayed buried forever — `getNextPending` filters them out, no automatic recovery, no UI surface. User saw "Some changes couldn't sync" toast on every reload.

**The fix — architectural, not a one-off migration.** Two changes to the sync engine:

1. **[`src/lib/sync/queue.ts`](src/lib/sync/queue.ts)**:
   - `MAX_RETRIES` is now exported.
   - `markComplete` resets ALL `failed` rows (`status='pending', retry_count=0, last_error=NULL`) after each successful sync. Rationale: a success proves the dependency landscape changed; give every failure another epoch's worth of retries. `MAX_RETRIES` still caps genuinely-broken rows.
   - `resetStaleInFlight` does the same reset for `failed` rows on app startup, so a freshly-reloaded app with no pending work still un-buries stuck rows.

2. **[`src/lib/sync/engine.ts`](src/lib/sync/engine.ts)**: when an entry crosses `MAX_RETRIES`, fires a distinct `Sentry.captureMessage` with `tag: source: 'sync-engine-permanent-failure'`. Filterable in Sentry dashboards without the per-attempt failure noise.

**Verified end-to-end.** All 10 previously-stuck queue rows (3 tracking_elements, 2 sessions, 2 drill_results, 3 element_values) confirmed in Supabase after the next reload. Toast no longer fires.

**Loose end fixed:** [`src/features/session-logging/repositories/drill-result.repository.ts:127-134`](src/features/session-logging/repositories/drill-result.repository.ts#L127-L134) `updateElementValue` was writing locally but never calling `appendToQueue` — found during audit, separate from the toast bug. ## How modal sheet headers work in this app

**Component:** [`src/shared/components/ModalHeader.tsx`](src/shared/components/ModalHeader.tsx). Exports `ModalHeader`, `MODAL_HEADER_HEIGHT` (88), `MODAL_HEADER_CONTENT_BOTTOM` (62).

**Design spec captured in the component:**
- Absolute-positioned, 88pt tall, `zIndex: 10`. Sibling of `<Screen>`, NOT a child.
- Background: `GradientBlurBackground` filling with `fadeStart={0.55}` (full blur 0→48pt, fades to clear by 88pt). Platform-conditional require — iOS uses `modules/GradientBlurView`, Android falls back to `BlurView` from `expo-blur` (intensity 30, tint light). Mirrors the pattern at `src/shared/components/CollapsibleHeader.tsx:13-24`.
- Inner row: `marginTop: 12, height: 50`, sits y=12–62. Below that is fade-zone only.
- Action buttons: outer `Pressable` is the touch target (`touchTargets.min` = 44pt); inner View is the visible 50×50 circle (`borderRadius: 25`, `backgroundColor: colors.borderDefault`). Phosphor icon inside: `size={20}, weight="bold", color={colors.textPrimary}` (or `colors.textDisabled` when the action is disabled).
- Title: `flex: 1, textAlign: 'center'`, `typography.titleMedium`, `colors.primary500` (brand purple), `numberOfLines={1}`.
- If only one action is provided, a same-width spacer renders on the other side so the title stays visually centered.

**Usage:**
```tsx
import { MODAL_HEADER_CONTENT_BOTTOM, ModalHeader } from '@/shared/components/ModalHeader';

return (
  <>
    <ModalHeader
      title="Settings"
      leftAction={{ icon: 'close', onPress: () => router.back(), accessibilityLabel: 'Close' }}
      // Optional:
      rightAction={{ icon: 'check', onPress: handleSave, disabled: !canSave, accessibilityLabel: 'Save' }}
    />
    <Screen edges={['bottom']}>
      <ScrollView
        contentContainerStyle={[styles.content, { paddingTop: MODAL_HEADER_CONTENT_BOTTOM + spacing.md }]}
      >
        ...
      </ScrollView>
    </Screen>
  </>
);
```

**Icon types currently supported:** `'close' | 'back' | 'check' | 'add'`. To add more, edit `IconType` and `renderIcon` in [`ModalHeader.tsx`](src/shared/components/ModalHeader.tsx).

**Critical layout detail — paddingTop.** Use `MODAL_HEADER_CONTENT_BOTTOM + spacing.md` (= 78pt), NOT `MODAL_HEADER_HEIGHT + spacing.md`. The 26pt below the icon row is intentional fade-zone for content scrolling under — content should sit right below the icons, not below the full blur view, otherwise there's a visible empty gap.

**FlatList screens need special structure.** A wrapper `<View>` with `paddingTop` will trap the FlatList content below the header — content can't scroll under and the blur effect is dead. Pattern that works:
```tsx
<ModalHeader ... />
<Screen edges={['bottom']}>
  <View style={styles.container}>  {/* no paddingTop here */}
    <FlatList
      contentContainerStyle={[styles.list, { paddingTop: MODAL_HEADER_CONTENT_BOTTOM + spacing.md }]}
      ListHeaderComponent={<OfflineBanner />}  {/* if needed */}
      ...
    />
  </View>
</Screen>
```
Same for `ScrollView` / `KeyboardAwareScrollView` — `paddingTop` lives on the scrollable's `contentContainerStyle`, not on a wrapper. For screens that need to render `<OfflineBanner />` full-width inside a padded scroll content, wrap it in `<View style={{ marginHorizontal: -spacing.md }}>`.

**Layout config.** In [`app/(settings)/_layout.tsx`](app/(settings)/_layout.tsx), every push-navigated route inside the modal sheet sets `headerShown: false`. The four `presentation: 'modal'` sub-routes (`activities/create`, `child/edit-profile`, `child/measurement-edit`, `child/external-activity-edit`) still use native headers — they don't have the push-transition glitch since they slide up rather than push.

## Folder structure for shared design components

This codebase keeps shared components at [`src/shared/components/`](src/shared/components/). One file per component, flat layout (not nested per feature). Examples:
- `ModalHeader.tsx` — modal sheet header (this session's addition).
- `CollapsibleHeader.tsx` — Home tab scroll-collapse header.
- `Screen.tsx`, `Button.tsx`, `Input.tsx`, `BottomSheet.tsx`, etc.

Feature-specific components live inside the feature folder (e.g. `src/features/activity-builder/components/`). The rule: don't extract to `shared/` until there's a second consumer.
